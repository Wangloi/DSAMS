# AI Coding Assistant Guidelines (AGENTS.md)

This file defines the mandatory operational protocol for AI coding assistants working in the **OSAMS / DSAMS** repository.

---

## 1. Prime Directives for AI Assistants

1. **Read `PROJECT_CONTEXT.md` First**: Before beginning any non-trivial development task, consult [`PROJECT_CONTEXT.md`](file:///c:/laragon/www/DSAMS/PROJECT_CONTEXT.md). Use its **Task-to-File Lookup Index (Section 24)** to identify relevant files. For exhaustive database column definitions, refer to [`DATA_DICTIONARY.md`](file:///c:/laragon/www/DSAMS/DATA_DICTIONARY.md).
2. **Verify Before Modifying**: Never assume a file, class, method, or route exists solely because it was documented. Always open and verify the target file's current state before applying edits.
3. **Avoid Repository-Wide Scans**: Do not blindly grep or scan the entire repository unless information is missing, obsolete, or insufficient.
4. **Make Minimal, Surgical Changes**: Make the smallest safe edit necessary to solve the user's issue. Do not perform unrelated refactoring, reformatting, or dependency changes.
5. **Preserve Architecture & Design Systems**:
   - Maintain the multi-guard authentication structure (`admin`, `program_head`, `student`).
   - Use Tailwind CSS v4 conventions (`@theme`, modern CSS variables; do **not** create a `tailwind.config.js`).
   - Follow existing React 19 + TypeScript + Inertia.js patterns.
6. **Keep `PROJECT_CONTEXT.md` Up to Date**: When introducing a new route, migration, model, service, or architectural pattern, update `PROJECT_CONTEXT.md` to reflect the change.
7. **No Hallucinations**: Never claim a feature, test, or security control works unless you have verified it in the source code or executed a test.
8. **Clarify Ambiguities**: If a user request involves destructive operations (e.g., dropping tables, resetting passwords in bulk, altering attendance logs), request confirmation first.

## 2. Non-Negotiable Project Constraints

| Domain | Strict Constraint |
|---|---|
| **Authentication** | The default `users` table was dropped. Do **not** query `App\Models\User` for authentication. Use the specific guard models: `AdminUser` (`admin`), `ProgramHead` (`program_head`), or `Student` (`student`). |
| **CSS / Styling** | Uses **Tailwind CSS v4** via `@tailwindcss/vite` and `tw-animate-css`. Styles are declared in [resources/css/app.css](file:///c:/laragon/www/DSAMS/resources/css/app.css). Do not suggest Tailwind v3 configs. |
| **Dev Environment** | Concurrently runs 4 services via `composer run dev` or `npm run dev:all`: Laravel HTTP server (port 8000), Queue worker, Vite dev server (port 5173), and the Node.js Socket.IO server ([socket-server](file:///c:/laragon/www/DSAMS/socket-server)). |
| **QR Attendance** | Two distinct flows: (1) Scanning physical Student ID barcodes/QRs via camera/scanner; (2) Dynamic rotating session QRs generated by [DynamicAttendanceQrController](file:///c:/laragon/www/DSAMS/app/Http/Controllers/DynamicAttendanceQrController.php) with 30s server-cached tokens. |
| **Geofencing** | Geolocation check-ins use Haversine distance calculations in [GeofenceValidationService](file:///c:/laragon/www/DSAMS/app/Services/Attendance/GeofenceValidationService.php). Frontend maps use **Leaflet**. |
| **Student Registration** | Public 2-step registration is active via [StudentRegistrationController](file:///c:/laragon/www/DSAMS/app/Http/Controllers/StudentRegistrationController.php) (`/register`) + post-login profile completion. Do not disable or bypass this workflow. |
| **Dropped Modules** | `announcements`, `found_items`, and `lost_reports` tables were dropped in migration `2026_05_18_000001`. Do not query these tables without reintroducing the migration. |
| **One Device Policy** | Students are subject to device binding ([DeviceBindingService](file:///c:/laragon/www/DSAMS/app/Services/Auth/DeviceBindingService.php)) tracking `device_uuid` to prevent proxy attendance check-ins. |
